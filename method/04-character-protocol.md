# 人物構築プロトコル — 人格を育てる手法

この文書は、**一人の人物（キャラクター）を人格として育てる**手順を定める。
憲法第2条（アンカー）と第3条（骨→肉のセオリー）を、物語ではなく**人**に対して適用したもの。

人物は二つの立場で現れる。どちらも本プロトコルで構築する。

- **人物型アンカー** … その人物が物語の核（憲法第2-2条）。外側の物語はこの人物の核へトレースして組む。
- **配役（Cast）** … アンカーに奉仕する肉（憲法第3条 肉4）。アンカーの抽象面のどの面を体現するかで置く。

> 立場が違っても、育て方（本プロトコル）は同じ。違うのは**何にトレースするか**だけ
> （アンカー人物は物語の核そのもの／配役は上位のアンカーへ従属）。

---

## 1. 人物の核＝二面を持つ固定点（憲法第2-1条の人物版）

物語アンカーが `Scene＋Message` なら、人物は次の二面で固定する。

- **核（抽象面・ものさし）** … その人物の中心にある**矛盾／傷／欲求**と、それが放つ**魅力（読者への約束）**。
  最深 Locked。「この台詞・行動は核を露見／奉仕させるか」が**その人物専用のものさし**になる。
- **原型反応（具体面）** … 核を体現する一つの「**刺激 → 反応**」。これを見れば「その人だ」と分かる signature。
  半 Locked（誰に・どの台詞で、は Open として下流に委ねてよい）。

魅力は「刺激に対する、その人ならではの反応」から生まれる。凡庸な反応との差分こそが魅力の正体である。

---

## 2. 積み上げ順（人物版の骨→肉）

憲法第3条を人物へ適用する。**骨は順序固定・必須、肉は自由順**。
どの層も上位（核、または人物がトレースするアンカー）へのトレーサビリティを持つ（憲法第4条）。

### 骨（順序固定・Locked 寄り）

1. **核（Core）** … 矛盾／傷／欲求 ＋ 魅力。あわせて **原型反応** と **欲求と恐れ（内的対立）** を置く。
   欲求と恐れは人物の中の「壁」であり、外的対立軸（`spec/10-opposition`）の人物内投影。
   ここに **禁則（この人物が絶対にやらないこと）** を一つ以上明記する（審査 2-8）。
2. **声と知覚（Voice）** … その人物の語彙・リズム・着眼（何を見て何を見ないか）。
   生成物の一貫性はここで決まる。台詞を他キャラに差し替えても成立するなら声が立っていない（審査 2-7）。

### 肉（自由順・Open 寄り）

3. **関係（Relations）** … 座組（キャストの集合）の中での差分。
   並列するキャラは**壁の種類・立場・感情の温度を全員別の値にする**（審査 2-3 重複審査）。
   関係は「二人セットで何が生まれるか」で設計する（均衡・分担・対位）。
4. **変化（Arc）** … 因果の背骨（`spec/30-spine`）に沿って、核がどう試され・露見し・変わるか。
   各段階を spine のビートへ語幹参照でひも付ける（後述4節）。

---

## 3. 審査（Locked 昇格の関門）

人物の各要素も `01-review-protocol.md` の関門を通す。特に効くのは：

- **抽象面への奉仕（§1）** … アンカー人物なら「核」に、配役なら「上位アンカーの抽象面」に奉仕しているか。
- **機構審査（2-1）／実害審査（2-2）** … 動機に検証可能な因果と具体的な犠牲があるか。
- **重複審査（2-3）** … 座組内で軸の値が全員違うか。
- **反転試験（2-5）** … 「それをやったのは本当にこの人物か」を入れ替えて検討する。
- **声の一貫性（2-7）／禁則審査（2-8）** … 人物専用の二項。声が立っているか、やらないことが言えるか。

昇格の手順・診断語彙は `01-review-protocol.md` に従う。

## 4. ドキュメント配置とトレーサビリティ

人物は `spec/40-cast/<NN>-<character>/` の**フォルダ**として持ち、層別ファイルで育てる
（構成規約 `02-document-layout.md` 第2節）。

```
spec/40-cast/10-<character>/
├── 00-core.<status>.md        # 核 ＋ 原型反応 ＋ 欲求と恐れ ＋ 禁則
├── 10-voice.<status>.md       # 声と知覚
├── 20-relations.<status>.md   # 座組内の差分
└── 30-arc.<status>.md         # spine 沿いの変化
```

- **語幹参照**（構成規約 第3-3節）：`spec/40-cast/10-charlotte`、サブ要素は
  `spec/40-cast/10-charlotte#core`、`#voice`、`#arc-beat-7` のように `#` で指す。
- **ステータス（信頼度）はファイル単位**。核だけ先に `.locked`、声はまだ `.draft`、が可能。
  これが「フォルダ／キャラ」を採る理由（1ファイルだと核だけ凍結できない）。
- **人物型アンカーの場合**：核の実体はこの `00-core` に一度だけ書き、`spec/00-anchor` はそれを
  **語幹参照で指すだけ**にする（実体を二重化せず、矛盾掃引・語幹唯一性を守る）。

## 5. アンカー人物と配役の違い（トレースの向きだけ）

| | 人物型アンカー | 配役 |
|---|---|---|
| 立場 | 物語の核そのもの | アンカーに奉仕する肉 |
| ものさし | この人物の**核** | 上位アンカーの**抽象面** |
| トレース先 | 外側（対立・背骨・他配役・世界）が**この人物へ**トレース | この人物が**上位アンカーへ**トレース |
| 衝突時 | 正アンカーとして扱う（正が勝つ／憲法第2-4条） | アンカーに従属。アンカーを上書きしない |
| 育て方 | 本プロトコル（2節） | 本プロトコル（2節）— 同じ |

配役の核が上位アンカーに**対位法（カウンターポイント）**を与えるのは歓迎する（副アンカーと同じ効用／憲法第2-4条）。
ただしそれは「アンカーと矛盾しない、または意図的な対立として設計されている」ことを明示した場合に限る。
