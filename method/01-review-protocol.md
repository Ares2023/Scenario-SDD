# 審査プロトコル — Locked 昇格の検問所

この文書は、要素（アンカー・仕様・計画・生成物）を
**`.draft`（Open）から `.locked`（Locked）へ昇格させてよいか**を判定する関門を定める。

憲法第5条「人間の承認をもって初めて Locked になる」を、**何をもって承認とするか**まで具体化したもの。
ステータス＝信頼度（`02-document-layout.md` 第3-2節）である以上、
**審査を通っていないものを信頼してはならない。**

---

## 0. 統治する姿勢：迎合しない

審査の目的は承認ではなく、**穴を見つけること**。

- 案を昇格させる前に、**却下理由を自分から探す**。見つからなければ初めて通す。
- 「良さそう」で通さない。作者自身が書いた設定にも穴があれば指摘する。
- 昇格は「反論が尽きた」ことの結果であって、賛成の多さではない。

この姿勢が崩れると信頼度の意味が失われ、`.locked` が「ただの古い draft」に堕ちる。

---

## 1. 最優先審査：Message への奉仕

すべての要素は、まずこれを通す。

> **その要素は、アンカーの Message（＝この物語の評価基準）に奉仕しているか。**

奉仕していない要素は、どれだけ巧くても不要か有害。
Message はアンカーが持つ抽象面であり（憲法第2-1条）、生成物の良し悪しを裁く唯一のものさし。

---

## 2. 審査項目

以下を必ず通す。一つでも落ちたら `.draft` のまま差し戻す。

### 2-1. 機構審査（Mechanism）
**その行動が結果を生む「仕組み」を一文で書けるか。**
書けなければ動機・因果が甘い。「〜だから〜した」の間に**検証可能な因果**が要る。

### 2-2. 実害審査（Real harm）
**その罪・過ち・葛藤に、具体的な犠牲者か機会損失があるか。**
心情だけでは罪にならない。「待たせた」は、待ったことで**何が失われたか**が無ければ実害ゼロ。

### 2-3. 重複審査（Duplication）
**並列する複数要素（キャラ等）は、軸の値が全部違うか。**
壁の種類／立場／感情の温度／その日の行動——一つでも被っていたら差し替える。

### 2-4. 伏線監査（Foreshadowing audit）
**新規に作る前に、既存テキストの未使用要素を洗い出し、回収できないか探す。**
作者本人が忘れている描写に価値があることが多い。

### 2-5. 反転試験（Inversion test）
**「誰がそれをやったのか」を入れ替えてみる。**
歪めたのは本人か外部か。愛したのはどちらか。素朴な配置より反転のほうが強いことが多い。

### 2-6. 矛盾掃引（Contradiction sweep）
**同じ事項が複数箇所で違う記述になっていないか。**
仕様を更新したら、必ず他ファイルの該当箇所も語幹参照から辿って直す（憲法第4条）。

---

## 3. 診断語彙（却下理由の共通語）

差し戻すときは診断名を添える。合意の履歴（`decisions/`）に残す語彙。

| 診断名 | 意味 |
|---|---|
| **機構不成立／未説明** | 原因と結果の間が飛んでいる |
| **実害ゼロ** | 罪だと言っているが、失われたものが無い |
| **私欲のみ** | 動機が自己利益だけで、人物の他の行動と矛盾する |
| **能力と行動の不整合** | 持っている力なら別の行動を取れるはずなのに取らない |
| **重複** | 既存要素と役割・軸が被る |
| **概念先行** | テーマは綺麗だが、感情の実体が無い |
| **主体の取り違え** | 「誰がそれをしたか」の配置が凡庸 |

---

## 4. 昇格の手順（draft → locked）

1. 対象の `.draft` に対し、第1〜2節の審査をすべて適用する。
2. 落ちた項目は診断名を付けて差し戻し、`decisions/` に却下理由と代替案を追記する。
3. 全項目を通過し、人間が承認したら `.draft` → `.locked` へリネームする。
4. 昇格が上位仕様に波及する場合は、矛盾掃引（2-6）を仕様全体へ回してから確定する。

`plans/` の**受け入れ基準**は、この審査項目を当該単位向けに具体化したものとして書く。
計画が `.locked` になる＝受け入れ基準が審査を通った、ということ。

---

## 5. 推奨手法（審査を通しやすくする生成側の作法）

- **既存テキストからの回収** — 未使用の描写を伏線として拾う（2-4 と対）。
- **制約を生成器として使う** — 「その時代に○○が無い → だから△△が起こる」。設定を縛りでなく発想源に。
- **抽象的な罪に具体的な犠牲を接続する** — 実害ゼロ（2-2）を回避する。
- **全員に同じ軸を通し、値を全部変える** — 重複（2-3）を回避する。
- **テーマと仕掛けを一致させる** — 要素の機能が Message の体現になっている状態を狙う。
